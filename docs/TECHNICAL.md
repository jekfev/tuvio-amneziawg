# VPN для ТВ — per-app AmneziaWG для Tuvio / YaOS

Модуль `:tv` в форке официального [amneziawg-android](https://github.com/amnezia-vpn/amneziawg-android).
VPN-протокол, криптография и backend — официальные (`:tunnel`, amneziawg-go v3.1.20260814).
Здесь только TV-интерфейс, per-app allowlist, импорт с USB, переподключение и диагностика.

**Через VPN идут только отмеченные приложения.** Остальные приложения телевизора работают напрямую.

## Сборка

Нужны JDK 17, Android SDK (platform 36, build-tools 36.0.0, NDK 26.1.10909125, CMake 3.22.1),
на macOS — `flock` и GNU `sha256sum` (`brew install flock coreutils`, gnubin в PATH).
**Путь к репозиторию не должен содержать пробелов** — Makefile backend'а это не переносит.

```bash
./gradlew :tv:assembleDebug
./gradlew :tv:assembleRelease
```

APK:
- `tv/build/outputs/apk/release/tv-release.apk` — для установки на ТВ;
- `tv/build/outputs/apk/debug/tv-debug.apk` — отладочный (ставится рядом, id `tv.splitvpn.awg.debug`).

Release подписывается ключом из `tv/keystore.properties` (не в git). Без этого файла —
debug-ключом. Обновлять приложение на ТВ можно только APK с той же подписью.

ABI: `armeabi-v7a` + `arm64-v8a` (переопределить: `-PtvAbis=armeabi-v7a`). Точный ABI Tuvio
не удалось прочитать (ADB в YaOS скрыт) — поэтому в APK обе ARM-архитектуры, система выберет нужную.
Фактический ABI показывает экран «Диагностика».

## Установка на Tuvio (YaOS, Android 11)

1. Скопируйте `tv-release.apk` и файл конфигурации (`.conf` или `.vpn` из Amnezia) на флешку.
2. Вставьте флешку в телевизор, откройте APK файловым менеджером телевизора.
3. Если YaOS спросит — разрешите установку из неизвестных источников для этого файлового менеджера.
4. Запустите «VPN для ТВ» из списка приложений.

Разрешения: VPN (системный диалог при первом подключении), уведомления (необязательно),
автозапуск после загрузки. «Доступ ко всем файлам» — только если понадобится запасной
встроенный выбор файла (см. ниже). Google Play Services не нужны.

## Использование

1. **КОНФИГУРАЦИЯ → ИМПОРТИРОВАТЬ С USB** → системный выбор файлов → флешка → файл.
   Поддерживаются `.conf` AmneziaWG/WireGuard и `.vpn` / `vpn://…` из клиента Amnezia.
   Файл копируется во внутреннюю память — флешку можно извлечь.
2. **ПРИЛОЖЕНИЯ** → OK на нужных приложениях (YouTube, браузер…) → СОХРАНИТЬ (или Back → Сохранить).
3. **ПОДКЛЮЧИТЬ** → в системном окне «Запрос на подключение» нажмите OK (один раз).
4. **ДИАГНОСТИКА → ПРОВЕРИТЬ ПОДКЛЮЧЕНИЕ**: покажет внешний IP через VPN и напрямую.

Если флешки не видно в системном выборе — **ВСТРОЕННЫЙ ВЫБОР ФАЙЛА**. На Android 11 он видит
`.conf` только с разрешением «Доступ ко всем файлам» (кнопка на экране; если в прошивке нет
такого экрана — `adb shell appops set tv.splitvpn.awg MANAGE_EXTERNAL_STORAGE allow`).

## Журнал

Приложение пишет журнал в свою внутреннюю память (`files/logs/vpn.log` + `vpn.log.1`, по ~512 КБ):
запуск, подключение/отключение, смена состояния, ошибки, обрывы сети, переподключения,
импорт конфигураций, изменение списка приложений, падения. Ключи и текст конфигурации не пишутся.

**ДИАГНОСТИКА → СОХРАНИТЬ ЖУРНАЛ НА ФЛЕШКУ** → в системном окне выберите флешку → «Сохранить».
Получится `vpn-log-ГГГГ-ММ-ДД-ЧЧММ.txt` с шапкой (версия, устройство, ABI, состояние, список
приложений) и журналом. Если системного окна нет — файл пишется прямо в корень флешки
(нужно разрешение «Доступ ко всем файлам»).

## Как это устроено

- `vpn/PerAppConfig.kt` — из сохранённого `.conf` удаляются любые `IncludedApplications` /
  `ExcludedApplications`, вставляется `IncludedApplications = <выбранные пакеты>`. Всё остальное,
  включая Jc/Jmin/Jmax/S1–S4/H1–H4/I1–I5, разбирает официальный парсер без изменений.
  Официальный `GoBackend` вызывает `VpnService.Builder.addAllowedApplication()` для каждого пакета;
  `addDisallowedApplication()` не вызывается. Пустой список запрещён (это был бы full-tunnel).
- Само приложение тоже в allowlist (служебно): так проверка подключения ходит через туннель,
  а запрос «напрямую» идёт через явный выбор физической сети (владелец VPN это может).
- `vpn/TunnelController.kt` — все операции с backend'ом в одном потоке. Изменение списка
  приложений/конфигурации → DOWN, ожидание фактического уничтожения VpnService, новый Builder, UP.
- Список приложений — `PackageManager`, только с `LAUNCHER`/`LEANBACK_LAUNCHER` activity;
  выбранные сверху, остальные по алфавиту. Package name берётся реальный, ничего не захардкожено.
- Переподключение: потеря физической сети → через 8 с backend останавливается, «Нет сети» →
  при возврате сети туннель поднимается снова. Нет handshake 45 с или сервер перестал отвечать →
  повтор с backoff 3, 5, 10, 20, 40, 60, 120, 300 с. Отзыв VPN-разрешения/другой VPN — не воюем.
- Автоподключение (кнопка на главном экране): при запуске приложения и после загрузки ТВ
  (`BOOT_COMPLETED`), только если VPN-разрешение уже выдано. Процесс держит foreground-сервис.

## DNS и утечки — что гарантируется, а что нет

- Приложения из allowlist получают DNS-серверы из `DNS =` конфига; запросы идут через туннель.
- Если в конфиге `AllowedIPs = 0.0.0.0/0, ::/0`, весь IPv6 выбранных приложений тоже уходит
  в туннель; если у интерфейса нет IPv6-адреса, IPv6 просто недоступен (а не идёт мимо).
- Приложение со своим DoH/DoT (например, браузер с «безопасным DNS») сам выбирает резолвер,
  но его трафик всё равно идёт через туннель — провайдер его не видит. Перехватить или
  подменить такой DNS VPN-клиент не может. «100% защиты DNS» не заявляется.
- Приложения вне allowlist используют обычную сеть и DNS провайдера — так и задумано.

## Проверено

На эмуляторе Android 11 (API 30, arm64, без Google Play) с реальным сервером пользователя
и двумя тест-приложениями (`tools/probe`, только для тестов):

| Проверка | Результат |
|---|---|
| Импорт `.vpn` через системный picker пультом, удаление исходника, перезапуск | конфиг сохранён |
| Импорт `.conf` с виртуальной USB встроенным выбором | без разрешения `.conf` не виден; с ним — импорт ок |
| Handshake с сервером, «Проверить подключение» | VPN работает, IP через VPN ≠ IP провайдера |
| A в allowlist, B нет | A → IP VPN, B → IP провайдера; UID-диапазон VPN = {приложение, A} |
| Добавили B на лету | оба → IP VPN, туннель пересоздан ~150 мс |
| Убрали A | A → IP провайдера, B → IP VPN |
| 4 изменения списка подряд | без ошибок |
| Отключение/включение сети | backend остановлен, затем поднят сам |
| Недоступный сервер | «нет handshake за 45 с», повторы 3 → 5 с … |
| JVM-тесты (allowlist, AWG-поля, ошибки без секретов, реальный файл) | 5/5 |

На самом телевизоре автоматически не проверено: в YaOS у Tuvio в меню разработчика нет
отладки по USB/сети (ADB). Приёмку на ТВ нужно провести по чек-листу ниже.

## Чек-лист на телевизоре

1. Импорт с флешки → извлечь флешку → перезапустить приложение → конфиг на месте.
2. Отметить только YouTube → ПОДКЛЮЧИТЬ → статус «ПОДКЛЮЧЕНО».
3. Диагностика → Проверить подключение → «VPN работает», два разных IP.
4. Браузер НЕ в списке: открыть 2ip.ru → IP провайдера. YouTube работает.
5. Добавить браузер → Сохранить → 2ip.ru показывает IP VPN.
6. Убрать YouTube → он идёт напрямую.

## Известные ограничения YaOS

- ADB скрыт в меню разработчика — установка только sideload с флешки.
- Системный выбор файлов YaOS может не показывать USB — для этого есть встроенный выбор,
  но на Android 11 ему нужен «Доступ ко всем файлам».
- Автоподключение после загрузки зависит от того, доставляет ли YaOS `BOOT_COMPLETED`
  сторонним приложениям; многие ТВ при выключении пультом уходят в сон, а не перезагружаются
  (тогда туннель просто продолжает работать). Если не поднялся — откройте приложение, при
  включённом «Автоподключении» оно подключится само.
- Ошибка `UAPIOpen: mkdir /var` в logcat — безвредна, она же есть в официальном приложении.
